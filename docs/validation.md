## 2026-11-19 第二轮 Bug 复查

适用环境和验证边界同上。本轮未安装 MuJoCo、未运行本机物理/渲染、未连接服务器或真机。上一节计数是第一轮历史检查，本轮新增检查后的状态如下。

已修复：

- `mj_step` 积分后的派生物体姿态可能仍对应上一物理步：新环境在动作结束后刷新派生状态，使评分/图像与实测关节时间一致。
- 执行中原生错误或回调异常可能发生在部分动作已推进之后：异常锁存故障，拒绝继续执行；故障后的策略调用不再消耗时钟。
- IK 的常规 Rodrigues 公式在 180° 附近退化，可能得到零误差轴：增加稳定的旋转向量处理，并提前验证目标、旋转矩阵、初值和求解参数。
- 资产校验原来允许包内绝对路径，迁移后可能断链：要求相对路径；拒绝未打包外部纹理/高度场/skin/模型/includes；导入完成前自行校验；空场景哈希不能绕过验证。
- `unittest` 默认将跳过视为成功：增加严格 `run_tests.py`，零测试或任何跳过均不通过服务器验收；自定义配置和原始模型路径传递到对应回归。
- 无图像入口显式禁用 GL；图像入口显式应用 `--gl`，避免旧环境变量掩盖参数。纯 RGB 常量图像按空间变化检查，防止纯色图片因通道不同而误过。
- 验收增加完整依赖快照、源码逐文件哈希和依赖一致性阶段，不能仅凭 Git HEAD 标识未提交的实验代码。

实际执行结果：主机 Python 3.10 / NumPy 1.21.5 下，27 项 unittest 中 **15 项通过、12 项跳过**（3 项要求 Python 3.11 的配置测试、9 项 MuJoCo 物理测试）。3 项配置测试另以已安装 `pip._vendor.tomli` 适配 `tomllib.load` 单独执行，全部通过；因此共 18 项纯逻辑检查通过，但不代表 Python 3.11 原生安装验收。另以子进程验证严格测试入口在该主机上正确返回失败，未将物理跳过算作通过。Python 编译、Shell 语法和 `git diff --check` 通过。9 项物理测试及双相机人工复核必须在目标服务器执行。

源码复核还发现官方 DreamZero 快照只接受 1/2 个推理 `ip` 进程，常规加载路径没有四卡权重分片，并行异常可能仅打印 `Skipping parallelization`。此为源码结论，不是 4090 运行结果。完整流程记录了该限制，不提供虚假的四进程即跑通命令；本轮未修改官方快照。
